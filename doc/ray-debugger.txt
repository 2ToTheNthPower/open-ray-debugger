*ray-debugger.nvim*         Attach Neovim to paused Ray tasks

==============================================================================
INTRODUCTION                                            *ray-debugger*

ray-debugger.nvim is an open source frontend for the Ray distributed
debugger.  It lists tasks and actors that are paused on `breakpoint()` (or on
an unhandled exception with post-mortem debugging) and attaches |nvim-dap| to
the debugger port the Ray worker publishes in its cluster state.

No Node.js or npm is involved: the plugin is Lua, uses `curl` for the Ray
dashboard REST API and nvim-dap for the Debug Adapter Protocol connection.

See `doc/protocol.md` in the repository for the full protocol details,
including the exact Ray source files involved.

==============================================================================
REQUIREMENTS                                        *ray-debugger-requirements*

- Neovim 0.10 or newer (a synchronous fallback exists for older versions)
- nvim-dap (https://github.com/mfussenegger/nvim-dap)
- curl
- Ray >= 2.9 on the cluster with `debugpy >= 1.8` installed
- The modern debugger mode: `RAY_DEBUG` must not be set to `legacy`

==============================================================================
SETUP                                                   *ray-debugger-setup*

>lua
    require("ray-debugger").setup({
      dashboard_url = "http://127.0.0.1:8265",
      poll_interval_ms = 3000,
      notify_on_new = true,
    })
<
With lazy.nvim/LazyVim:

>lua
    {
      "2ToTheNthPower/open-ray-debugger",
      dependencies = { "mfussenegger/nvim-dap" },
      cmd = { "RayDebug", "RayDebugAttach", "RayDebugPostMortem",
              "RayDebugWatch", "RayDebugRefresh" },
      keys = {
        { "<leader>dR", function() require("ray-debugger").pick() end,
          desc = "Ray: Attach to paused task" },
      },
      opts = { dashboard_url = "http://127.0.0.1:8265" },
    }
<
With `keys` or `cmd` set, lazy.nvim lazy-loads the plugin: `:Lazy` lists it
as "Not Loaded" until a key or |:RayDebug| command is used.  Without `cmd`,
the commands don't exist until a key is pressed.  Add `lazy = false` to load
it at startup instead.

==============================================================================
USAGE                                                   *ray-debugger-usage*

1. Put `breakpoint()` in a Ray task or actor method and run the application.
   The `examples/` directory has ready-to-run demos: a single pause (with a
   `post-mortem` mode) and two tasks paused at once for trying the picker.
2. Run |:RayDebug| and pick the paused task from the list.
3. Debug with the usual nvim-dap commands.  Disconnect to let the task resume.

Post-mortem debugging: set `RAY_DEBUG_POST_MORTEM=1` in the cluster runtime
environment; failing tasks are frozen instead of failing so you can inspect
them.

==============================================================================
COMMANDS                                             *ray-debugger-commands*

:RayDebug
        List paused tasks in all configured clusters and attach to the
        selected one.

:RayDebugAttach {target}                            *:RayDebugAttach*
        Attach directly.  {target} may be `host:port`, a worker id, or a
        task id (prefix).

:RayDebugRefresh                                    *:RayDebugRefresh*
        Refresh the cached paused task list.

:RayDebugWatch [on|off]                             *:RayDebugWatch*
        Toggle background polling.  While watching, a notification is shown
        whenever a task starts waiting for a debugger.

:RayDebugPostMortem                                 *:RayDebugPostMortem*
        Show the recovered post-mortem traceback (quickfix) and the failing
        frame's locals (nvim-dap REPL) again.  See |ray-debugger-post-mortem|.

:checkhealth ray-debugger                           *:checkhealth-ray-debugger*
        Diagnose `curl`, nvim-dap, the debugger mode, and cluster
        reachability.

CONFIGURATION                                   *ray-debugger-configuration*

`setup()` accepts:

dashboard_url           string   Dashboard URL used when `clusters` is unset.
                                 Default: "http://127.0.0.1:8265"
clusters                table    List of clusters: { name, url, dap_host?,
                                 headers? }.  Overrides `dashboard_url`.
request_timeout_ms      integer  HTTP timeout.  Default: 5000
poll_interval_ms        integer  Background refresh interval, 0 disables.
                                 Default: 0
notify_on_new           boolean  Notify when new paused tasks appear while
                                 polling.  Default: false
picker                  function Custom picker: `fun(entries, on_choice)`.
                                 Default: |vim.ui.select|
attach.just_my_code     boolean  Passed to debugpy.  Default: false
attach.path_mappings    table    DAP `pathMappings`, e.g.
                                 `{ { localRoot = "/local", remoteRoot = "/remote" } }`
attach.skip_internal_frames
                        boolean  When Ray's `breakpoint()` suspends a frame
                                 inside Ray/debugpy plumbing, select the first
                                 user frame.  Default: true
attach.working_dir.enabled
                        boolean  Map tasks that run from a `working_dir`
                                 runtime env (every Ray Job) to the local
                                 project.  Default: true
attach.working_dir.local_root
                        string|function
                                 Local project root, or `fun(entry)`
                                 returning it.  Default: Neovim's cwd
attach.extra_args       table    Extra arguments for every attach request.
attach.disconnect_timeout_sec
                        integer  Disconnect timeout.  Default: 3
post_mortem.enabled     boolean  Recover post-mortem tracebacks.  Default: true
post_mortem.quickfix    boolean  Traceback in the quickfix list.  Default: true
post_mortem.repl        boolean  Exception and locals in the DAP REPL.
                                 Default: true
post_mortem.jump        boolean  Jump to the failing line.  Default: true

==============================================================================
POST-MORTEM                                     *ray-debugger-post-mortem*

With `RAY_DEBUG_POST_MORTEM=1`, Ray freezes a failing task so a debugger can
attach.  debugpy 1.8.0-1.8.5 then stops in the failing frame.  debugpy 1.8.6
and newer report Ray's worker stack instead of the traceback and fail the
`exceptionInfo` request, so the failing frame cannot be selected.

The plugin detects this and evaluates a small expression in Ray's
`_debugpy_excepthook` frame to recover the traceback: it fills the quickfix
list, jumps to the failing line, prints the exception and the locals of every
traceback frame in the nvim-dap REPL, and selects the hook frame so REPL
expressions can use `error` (the `sys.exc_info()` tuple).

API                                                     *ray-debugger-api*

require("ray-debugger").setup({...})
require("ray-debugger").pick()
require("ray-debugger").refresh(function(err, entries, warnings) end)
require("ray-debugger").attach(entry)
require("ray-debugger").attach_address("host:port")
require("ray-debugger").watch(enable?)  -- toggle background polling
require("ray-debugger").post_mortem()   -- re-show post-mortem traceback
require("ray-debugger").paused_count()
require("ray-debugger").status()      -- statusline component, e.g. "⏸ 2"

==============================================================================
TROUBLESHOOTING                             *ray-debugger-troubleshooting*

Run |:checkhealth-ray-debugger| first.

- "no paused Ray tasks found": the task has not reached `breakpoint()` yet,
  it already resumed, or the cluster uses `RAY_DEBUG=legacy`.
- Connection errors: the dashboard is not reachable; check `dashboard_url`.
- Attach hangs: the worker's debugger port is not reachable from your machine.
  Forward it (SSH tunnel or `kubectl port-forward`) and set `dap_host`.
